Product Overview 1.1 Context Diagram The Garment Production Management System (GPMS) is a software solution developed to replace the existing manual and informal management practices commonly used in small-scale, home-based garment production facilities. Prior to the introduction of GPMS, customer orders, production schedules, and workforce information were managed through handwritten notes, chat messages, and personal experience. This fragmented approach makes it difficult to track order progress, allocate workloads effectively, calculate wages and production costs accurately, and ensure timely delivery to customers. GPMS provides a centralized platform to manage customer orders, production processes, and operational activities in a structured and systematic manner. By digitalizing key workflows, the system aims to improve transparency, operational efficiency, and decision-making for owners and staff involved in garment production. The context diagram for GPMS Release 1.0 defines the system boundary and illustrates the interactions between GPMS and external entities, including customers and production staff. 1.2 Main Workflow 1.2.1 Create Order Request Workflow 1.2.2 Create production and production plan workflow 1.2.3 Production Part Assignment and Submit Workflow 1.2.4 Create issue log workflow 2. Requirement Appendix 5.1 Business Rules ID Rule Definition BR-01 All orders created by the customer must be reviewed and approved by the owner or Admin before a related production project can be initiated. BR-02 Production plans created by the PM, including tasks, unit prices, and assignments, must be approved by the owner before workers can submit daily output. BR-03 Workers can only view and submit work logs for production parts that they have been officially assigned to. BR-04 The total recorded output of a production part must not exceed the target quantity of the order. BR-05 Defective quantities are automatically excluded from valid output used for wage calculation. These quantities are only recalculated after being marked as “Fixed”. BR-06 Worker salary is calculated using the formula: Salary = output quantity × cost per unit in production parts - defect which can fix. BR-07 When a worker’s leave request is approved, the system automatically removes them from the available assignment pool during the leave period. BR-08 Customers can only cancel orders when the status is “Pending” or “Revision Required”. Once the order is in “In Production”, cancellation requires Owner intervention. BR-09 Production processes (task lists) can be saved as templates and reused for similar products to ensure consistency. 5.2 Application Messages List # Message code Message Type Context Content 1 MSG01 Inline Search No results found. 2 MSG02 Inline Error Form Validation This field is required. 3 MSG03 Inline Error Form Validation Invalid input format. 4 MSG04 Toast General Error An unexpected error occurred.
